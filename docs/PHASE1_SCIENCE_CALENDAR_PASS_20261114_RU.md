## 1. Реальные ошибки, обнаруженные при повторной проверке

1. В **собственном севообороте фермера** отсутствие дат промежуточной культуры позволяло старой проверке пропустить противоречие между двумя известными датами более удалённых этапов.
   Пример: уборка пшеницы 24.06.2026 → пар без дат → начало маша 10.06.2026. Ранее получали `missing_dates`, хотя уже известен конфликт; теперь `conflict`.
2. Если уборка первой культуры не указана, но посев следующей стоит раньше посева первой, конфликт также ранее скрывался.
3. Если уборка маша введена **раньше посева**, API возвращал `duration_days: -5`, что в научном UI выглядит как бессмысленная отрицательная продолжительность.
4. Даже при обнаруженном конфликте **пользовательский вариант A** мог продолжать показывать общий статус `compare`, тогда как B/C подсвечивали `calendar-conflict`.

## 2. Что исправлено

- `backend/app/calendar.py`: известные даты внутри объявленной пользователем последовательности теперь проверяются **всем списком по порядку событий**, а не только между соседними культурами с обеими датами. Неполные даты остаются в массиве `missing`, но известный конфликт получает приоритет.
- Календарный отрицательный интервал маша теперь возвращается как `duration_days: null`, с состоянием `conflict`. Для настоящих интервалов сохранён справочный диапазон Durdona 70–75 дней без фиктивной пригодности.
- `backend/app/service.py`: пользовательский baseline A тоже получает `calendar-conflict` и переводимый `calendarOverlap` в warnings, если реальные даты противоречат друг другу. B/C и water-risk логика сохранены.
- Добавлены 5 Python API regression-тестов, сначала **3 из них воспроизвели ошибки**, после исправления **5/5 PASS**.
- Добавлен отдельный Chrome regression-тест: 3 культуры с пропущенной серединой, A-конфликт в карточке, исправление даты, отсутствие ложного подтверждения, RU/UZ и запрет отрицательного роста. Встроен в `check_all.ps1` как `test:calendar`.

## 4. Чего исправления НЕ означают

- Корректная хронология **не доказывает**, что сорт вырастет в данной почве и получит достаточно воды.
- Результат фермерского A по шести агрономическим факторам остаётся **UNKNOWN**, пока нет валидированных полевых данных. Программа не объявляет его слабее/сильнее B/C.
- Осадки NASA IMERG не равны объёму воды в канале, ECe требует лабораторного подтверждения, картинка GIBS не выдаёт числовой NDVI.
- Нет нового подключения SMAP, Landsat, GAEZ или WaPOR и не изобретены спутниковые значения.
