### Новый полезный шаг именно из имеющихся NASA-данных
`backend/app/repository.py::planting_windows` использует оригинальные ежедневные `IMERG_PRECTOT` и для каждого 75-дневного окна суммирует реальные осадки, затем выдаёт **среднее, исторический минимум и максимум 2000–2025**, вместе с уже имеющимися показателями жары и заморозков. Эти числа рассчитываются, а не рисуются. В интерфейсе явно подписано: **региональные осадки — это не подача воды из канала и не потребность культуры**. В backend есть независимый тест, восстанавливающий статистику непосредственно из ежедневных NASA значений.

NASA POWER прямо указывает пространственные особенности:
- IMERG — около **0.1° (~10 км)**, daily UTC, различие Final/Late Runs и задержки; 2000–2025 — исторический ряд.
- T2M из MERRA2/POWER — сеточный реанализ порядка **0.5°×0.625°**, не метеостанция на поле.
- NASA POWER рекомендует исключать последние ~3.5 месяца при анализе трендов IMERG Final Run; наш архив заканчивается 31 декабря 2025, поэтому не включает спорные последние месяцы ноября 2026.
Источники: https://power.larc.nasa.gov/docs/methodology/data/sources_meteorology/ и https://power.larc.nasa.gov/docs/methodology/.

## 2. Следующий NASA продукт, если останется время: SMAP L4 (научно полезен, но не должен сломать MVP)

**Важное уточнение из свежей официальной документации:** NASA POWER уже описывает *SMAP L4_SM* через High-Resolution toggle или алиасы. Это ассимиляция SMAP L-band brightness temperature в Catchment land-surface model, **~9 км**, UTC daily, начиная с 31 марта 2015; параметры `SFMC` (0–5 см), `RZMC` (корневая зона), `PRMC` и percentiles. Официальная методика:
https://power.larc.nasa.gov/docs/methodology/data/sources_hydrology/
https://power.larc.nasa.gov/docs/tutorials/data-access-viewer/user-guide/

В нашей попытке получить точный алиас из POWER Manager API запрос HY/DAILY 14 ноября возвратил HTTP 422; **конкретный валидный запрос, значение SMAP для Хорезма и QA ещё не доказаны**. Следовательно:
- не создавать фиктивное поле `soil_moisture=28%`;
- не заменять ECe почвы / фактический полив значением SMAP;
- если достаём ряд, сохранять **исходный ответ API** с источником, версией, параметром, единицами, координатами, временем, SHA‑256, признаками валидности, числом пропусков;
- отдельная локальная климатическая визуализация «региональная модельная влажность почвы SMAP L4» допустима только после проверки продукта и корректности масштаба; не трактовать ~9 км как влажность поля;
- не пытаться многократно опрашивать API по одному и тому же месту: NASA POWER просит минимизировать повторные запросы к одной ячейке.

Альтернативный отдельный официальный продукт: NSIDC `SPL4SMGP` Level-4 soil moisture geophysical data (версия определяется по действующей продуктовой странице), требует проверки дат, качества, геопривязки. https://nsidc.org/data/smap/data

## 3. Численный NDVI: реальный план, почему сейчас НЕ сделан

### MODIS MOD13Q1.061
- NASA `MOD13Q1` 250 м, 16-дневные композиты, имеет оригинальный `250m 16 days NDVI` и `250m 16 days pixel reliability`, отдельный `VI Quality` с флагами облаков, аэрозоля и полезности.
- Исходные значения **не являются непосредственно десятичным NDVI**: требуется масштаб, проверка fill/valid_range и QA. См. NASA LAADS: https://ladsweb.modaps.eosdis.nasa.gov/filespec/MODIS/61/MOD13Q1
- Нельзя вывести числовой NDVI поля из оттенков GIBS PNG. Для анализа потребуются **оригинальный scientific raster**, дата/тайл, преобразование координат, классификация QA, валидные пиксели, реальные границы поля и честная статистическая неопределённость.
- 250 м часто покрывают несколько полей, каналов и дорог, поэтому для границ конкретного малого участка этого может оказаться недостаточно.

### Landsat Collection 2 Level 2 (USGS/NASA)
- Спектральное отражение поверхности порядка **30 м**; scaling `SR = DN×0.0000275−0.2`, исключить fill pixel и облака/тени с `QA_PIXEL`, учесть `QA_RADSAT` и `SR_QA_AEROSOL`.
- Для Landsat 8/9 NDVI из соответствующих red/NIR surface reflectance после масштабирования; не использовать raw RGB/PNG.
- Официально: https://www.usgs.gov/landsat-missions/landsat-collection-2-surface-reflectance ; https://www.usgs.gov/landsat-missions/landsat-collection-2-quality-assessment-bands .
- Без конкретных дат, сцен и границ поля числовой NDVI в AgroSat сегодня **не вводится**.

### Почему не добавлять ECOSTRESS/GLDAS/SRTM/GEDI для «красоты»
Для текущего A/B/C решающими ограничениями остаются календарь, вода, засоление и культура. Дополнительная термальная/DEM/лесная карта без измерений и QA не увеличивает проверяемость решения.

## 5. Приоритеты для максимально сильной конкурсной версии

**DONE в локальном коде**: NASA daily GPM/IMERG, MERRA2/POWER, 75-day rain/heat/frost; A/B/C; structured farmer crop rotation, field chronology/missing/conflict/review states, optional measured ECe/pH/irrigation with source/period; four FAO/ICARDA reference crops with links; dual themes and EN/RU/UZ; 7 English slides; scientific tests.

**ВОЗМОЖНО ПОЗЖЕ, НЕ ГОТОВО:** валидный численный SMAP L4 / MOD13Q1 / Landsat с QA; независимый Узгидромет по тем же датам; фактические измерения ECe/воды; доказанный cultivar-specific урожайный ответ/экономика.

**Конкурсная приоритетность:** сначала работающая проверенная версия + public source credits/AI disclosure + 7 слайдов + реальная отправка до дедлайна, только затем рискованная интеграция новых Earth Observation. Все 24 пункта NASA Resources интегрировать **не требуется**, часть применима исключительно к территории США.


## 6. Дополнительная проверка SMAP 14 ноября — фактический ответ, а не предположение

После изучения актуальной документации NASA POWER SMAP L4 (уровень 4; региональная модельная поверхностная и корневая влажность; ~9 км) выполнен **один ограниченный запрос** к `/api/temporal/daily/point` за 01.07–30.09.2025 для 41.55°N, 60.62°E:
`parameters=SFMC,RZMC&community=AG&longitude=60.62&latitude=41.55&start=20250701&end=20250930&format=JSON&time-standard=UTC`

HTTP **200**, NASA POWER Daily API **v2.10.3**, параметры `SFMC` и `RZMC`, единицы **m³/m³**, однако:
- `SFMC`: 92 дат, **0 действительных значений**; все 92 = `-999.0`;
- `RZMC`: 92 дат, **0 действительных значений**; все 92 = `-999.0`;
- исходный `header.sources` в ответе — пустой список, поэтому **фактическая привязка именно к SMAP этим ответом не подтверждена**.

Исходный ответ сохранён в gitignored исследовательском архиве `research/SMAP_POWER_ONE_QUERY_202507_202509.json` (без включения недостоверных значений в рабочий API). **Решение: числовую влажность SMAP НЕ внедрять** до повторной документированной проверки правильного источника/алиаса, наличия действительных показателей и QA. HTTP 200 сам по себе не является научным PASS.

## 7. Новая независимая работа о сортах маша (октябрь 2026)
Халимова Г. Б., Джураев М. Й., *Agrobusiness, Science and Technology* (30.10.2026), DOI **10.68372/zt1fw572**:
https://agrobiznesjournal.uz/index.php/ast/article/view/485

В аннотации указана длительность **70–76 дней для Durdona** и **83–90 дней для Hosildor** в изученных вариантах опыта, с влиянием сроков сева/обработки. Это важное подтверждение того, что даже внутри культуры нельзя применять одно фиксированное окно для всех сортов. Это **не доказательство такой же длительности на любом поле Хорезма**. AgroSat сохраняет осторожное 70–75-дневное окно из ICARDA 2022 и помечает введённые иные сроки как требующие сортовой проверки, а не как «невозможные».
